## Làm
1. `cloudinary.util.js`: cấu hình từ config, `uploadBuffer(buffer, folder)` bằng `upload_stream` trả `{url, publicId}`, `destroy(publicId)`.
2. `upload.middleware.js`: multer `memoryStorage`, chỉ jpg/png/webp, ≤ 2MB.
3. `POST /admin/uploads` (staff|admin, field `file`, query `folder`) và `POST /me/avatar` (thay ảnh cũ → gọi destroy).

## Ghi chú cho task sau
- `cloudinary.util.js`: cung cấp hàm `uploadBuffer(buffer, folder)` trả `{ url, publicId }` và `destroy(publicId)`. Hỗ trợ tự động fallback an toàn khi ở chế độ dev/test chưa có API key thực tế.
- `upload.middleware.js`: multer `memoryStorage`, kích thước tối đa 2MB, định dạng cho phép: JPG, PNG, WEBP. Cung cấp middleware `uploadSingle(fieldName)` và `uploadAvatar` (nhận linh hoạt cả field `avatar` hoặc `file`).
- Endpoint `POST /api/v1/admin/uploads`: yêu cầu quyền `staff` hoặc `admin`, nhận query `folder` (mặc định hoặc tự prefix `library/`), trả mã 201 `{ url, publicId }`.
- Endpoint `POST /api/v1/me/avatar`: upload avatar người dùng, tự động gọi `cloudinaryUtil.destroy(user.avatar.publicId)` nếu có ảnh cũ, lưu vào `user.avatar = { url, publicId }`.
